# 官方 SINet-V2 与本地数据、当前训练的只读对照

日期：2026-10-26。用户要求在现有训练继续期间检查。仅检查并形成这份报告；没有修改数据、训练代码、运行配置、划分或正在运行的进程，也没有启动额外训练、推理或监控。

## 结论

1. 本地CAM数据来源和当前CAM-only范围基本正确，不是少下载了NonCAM，也没有把GT_Edge或GT_Instance误当作对象分割GT。
2. 当前80轮任务是**项目PVTv2 RGB开发基线**，不是官方Res2Net SINet-V2训练复现。骨干、解码通道/注意力、训练量、增强、目标函数、优化器、调度和选模口径都有区别。此前官方权重的四指标对齐只核验了推理/评估链路，不证明当前训练方案与官方一致。
3. 实查发现两组相同RGB、不同GT的训练样本，其中老虎一组冲突明显。另有两张含少量灰度的训练GT，以及原始Info训练列表与文件目录的成员差异。需要记录并在下一版数据协议前人工审核，不能在本轮中途静默改数据。
4. 没有发现仅凭本次检查就必须立即中断本轮的流程故障；但本轮结果不能冒称官方训练复现或直接当成语义模块收益。

## 一、官方用了哪些数据

[论文V-A3](https://arxiv.org/html/2102.10274v2)采用CAMO与COD10K的联合训练集，不额外加入EXTRA；测试使用CHAMELEON、CAMO-Test、COD10K-Test。作者在[官方仓库讨论中的2022年回复](https://github.com/DengPingFan/SINet/issues/9)明确更新后的训练集合为4040张CAMO-Train与COD10K-Train样本；早期CPD1K/EXTRA说明不能混套到这一版。

| 用途 | 常用官方CAM范围 | 本地原始目录 | 当前实际使用 |
|---|---:|---:|---|
| CAMO训练 | 1000 | 1000 | 904训练、96开发验证 |
| COD10K伪装训练 | 3040 | 3040 | 排除5张与测试完全重复的图后，2748训练、287开发验证 |
| CAMO测试 | 250 | 250 | 官方权重已在250张上复核；本轮训练不读取 |
| COD10K伪装测试 | 2026 | 2026 | 官方权重已在2026张上复核；本轮训练不读取 |
| CHAMELEON测试 | 76 | 未发现 | 尚未评估 |

作者仓库还发布NC4K测试预测，不能由此把NC4K算作这套联合训练数据。本地目前也没有该测试集。

本地 `Dataset/TrainValDataset/Imgs` 确实有7000张：CAMO1000、COD10K-CAM3040、NonCAM2960；并非7000张都属于标准伪装分割训练范围。`TestDataset/COD10K/Imgs` 有4000张，其中CAM2026、NonCAM1974。当前清单已排除后两组NonCAM，**保留原始目录不等于当前仍在用NonCAM训练**。不要为了凑7000或10000张又把负样本加回标准CAM比较。

当前训练+开发验证4035=4040-5；实际优化器只接触3652张，383张只用于开发验证。这不是与作者使用全部4040张训练严格相同的设置，但保留独立开发集本身合理，需在论文/汇报中明确。历史数据准备先在含NonCAM的池中按内容哈希分组划分，再保持成员过滤NonCAM，所以不是重新按CAM类别分层后的精确90/10划分。

## 二、实际文件核验结果

### 已通过的检查

- 原始混合训练目录7000张RGB与7000张GT、CAMO测试250对、COD10K测试4000对，文件名配对没有缺失或多余项。
- 对本地CAM池4040张及CAM测试2276张，共6316条，实际解码检查尺寸、非空前景、图像SHA256、图像解码像素哈希。RGB/GT尺寸均一致；CAM GT均非空；清单引用图像均匹配记录的SHA256。
- 当前train/val/test之间没有相同RGB字节或相同解码RGB像素；发现的5对训练/测试相同图已经在`excluded`清单内，不进入当前训练或开发验证。未排查所有裁剪、缩放、重新压缩或同场景近重复，不能宣称完全不存在近重复泄漏。
- 本地混合目录中COD10K的3040训练图和2026测试图，逐文件与保留的 `COD10K-v2/COD10K-v2/{Train,Test}/Image` 完全一致；对应GT也分别与 `GT_Object` 的5066个PNG逐文件一致。没有混用GT_Edge/GT_Instance。
- 本地train.csv/val.csv哈希分别为`e91d51442af5094ff56ebfd563d1ee0b2eaf874cd98567e240056dcc09bb8c59`、`79ea687e69606fa143a27f127bf46527d74ed3ec22275c37eae3919708d23cbf`，与正在运行任务PROVENANCE记录一致。
- 额外重放当前第1轮的确定性裁剪/翻转/GT缩放参数：3652张没有因裁剪或缩放变成空目标，1张裁剪后保留的前景少于原前景一半。此项只覆盖第1轮，不外推全部80轮。

### 需要注意：两组相同RGB但GT不同

| 同图样本后缀 | 所在划分 | GT二值IoU | GT不同像素 |
|---|---|---:|---:|
| Tiger-2875 / Tiger-2880 | 两张均train | 0.423543 | 310109（图像17.305%） |
| Dragonfly-3568 / Dragonfly-3572 | 两张均train | 0.953637 | 13509（图像1.290%） |

完整ID前缀分别为`COD10K-CAM-2-Terrestrial-47-`和`COD10K-CAM-3-Flying-57-`。两组RGB文件字节完全相同，而GT不同；已查看四张GT并在服务器上复核相同IoU。老虎组不是简单的个别边缘像素抖动。它会给同一图像提供不一致监督，但只有4张训练条目，不能据此推断整体效果不佳的主因。

这四个GT也与本地保留原始COD10K-v2副本的GT_Object一致，说明不是当前加载器拿错实例/边缘标注。尚未另行下载并校验作者混合训练包，因此不能进一步宣称所有官方分发版本都完全相同。下一版可人工核对后决定保留、统一或去重，必须固定所有消融组同一规则；本轮没有删除或替换它们。

### 需要注意：原始Info文件与图像目录不完全一致

`COD10K-v2/COD10K-v2/Info/CAM_train.txt`实际3039条，格式正常、无重复行；实际Train/Image有3040张CAM图。

- Info中有、训练图目录没有：`COD10K-CAM-2-Terrestrial-23-Cat-1506`；该图实际位于本地测试目录。
- 训练图目录中有、Info没有：`COD10K-CAM-1-Aquatic-3-Crab-39`、`COD10K-CAM-3-Flying-59-Grasshopper-3638`。
- CAM_test.txt的2026条与测试图目录完全一致。

这是保留原始副本内部的元数据/文件版本一致性问题，不能仅看3040的数量就认定与作者发布的训练包逐ID完全相同。下一步需单独取得作者README链接的训练包核对成员；不应该把Info里提到的Cat测试图自行补进训练。

作者README也明确提示过训练/测试重复问题，但其列出的样本与我们这里按内容发现的5对并不完全相同；不能把两份记录强行当成同一问题。

### 两张含灰度的训练GT：不是立即故障

- `camourflage_00007.png`：RGB模式，转灰度后有253个取值，非0/255像素1655个，占0.1559%。
- `camourflage_00347.png`：L模式，8个取值，非0/255像素10个，占0.00986%。

服务器文件哈希与本地相同。当前训练会保留这些软值；BCE可以接受软目标，官方增强的双线性缩放/旋转也会引入灰度，不能把“不是纯二值”直接等同于坏文件。若未来要阈值化GT，应统一协议、保留原始来源并重新对照，不能现在临时修改。

## 三、训练设置逐项对照

官方依据为固定上游提交`5b9844c94d10a03b815c7c7039c194166a9a8ba3`的[MyTrain_Val.py](https://github.com/GewelsJI/SINet-V2/blob/main/MyTrain_Val.py)、[data_val.py](https://github.com/GewelsJI/SINet-V2/blob/main/utils/data_val.py)、`utils/utils.py`及论文IV-D。当前设置同时读取本地配置和服务器正在运行任务CONFIG/PROVENANCE确认，而非只看旧MyTrain默认值。

| 项目 | 官方SINet-V2 / 发布脚本默认 | 当前项目RGB正式开发训练 |
|---|---|---|
| 网络 | Res2Net50，channel32 | PVTv2-B2，channel64，RFB/NCD含CBAM |
| 初始化 | ImageNet Res2Net骨干 | ImageNet PVTv2骨干；随机COD解码器 |
| 实际训练图 | 标准联合训练池4040 | 3652，另383开发val，排除5重复 |
| 输入与归一化 | 352×352，ImageNet mean/std | 一致 |
| 优化器 | Adam，默认无weight decay | AdamW，weight decay=1e-4 |
| 初始lr | 1e-4 | 1e-4 |
| batch | 36 | 8 |
| 轮次 | 论文100；代码`range(1,100)`实际99 | 80 |
| lr衰减 | 每50轮/10；代码在第50轮开始前衰减 | 第30/60轮结束后/10 |
| 梯度裁剪 | 逐元素截断到[-0.5,0.5] | 全局范数裁剪到1 |
| 每输出损失 | weighted BCE + weighted IoU | 前两项 + 额外(1-soft E) |
| 深监督 | 四输出损失相加 | 四输出损失相加 |
| 数据增强 | 水平翻转、中心随机裁掉约0–30px、随机旋转、颜色/亮度/对比度/锐度增强、GT椒盐扰动 | 85%–100%窗口随机位置裁剪、水平翻转；无旋转或颜色增强 |
| GT缩放 | torchvision默认双线性，可能产生软边缘 | 最近邻，保留原始GT取值 |
| best选择 | 逐图minmax后的MAE；默认val_root指向CAMO测试目录 | 独立383开发val的raw MAE |
| 完整指标 | 标准PNG/归一化后四指标 | 每轮单独记录raw和标准兼容两套四指标，仍仅用raw MAE选best |

注意`use_ca=False`只关闭当前GRA里的额外ChannelAttention，不会取消RFB和NCD内已有CBAM，不能据此把当前网络称为“纯官方SINet-V2”。

80轮不是直接的“训练更少”结论：当前每轮457次更新、总36560次；按4040/batch36，官方每轮113次，99轮约11187次。但总图像呈现量、batch统计、lr对应更新数及增强均不同，所以不能仅对齐epoch或步数就宣称公平。

官方发布脚本的默认`val_root=./Dataset/TestDataset/CAMO/`确实涉及用CAMO测试标注选best；该默认不证明作者所有发布权重都按默认运行，也不应成为我们反复看测试集选模型的理由。当前独立383开发集更适合开发，但与作者发布设置不同，需要说明。

## 四、如何解释正在跑的这一轮

- 保留其“项目PVTv2 RGB长程开发基线”定位；不改运行中配置，不把此次诊断变成训练中途的超参调整。
- 后续直连/关系消融必须共用当前RGB的网络基础、划分、增强、损失、训练预算和选模规则，才能把差异归因到多区域/主辅关系；不能拿“当前模型 vs 官方发布权重”的差异直接证明关系模块有效。
- 若要声称“复现官方SINet-V2训练”，另开任务使用作者原始Res2Net网络、官方训练包和一致的训练目标/优化设置。那与已完成的“官方权重评估链路复核”是两件事。
- 正式对外比较前，优先确认训练包成员/重复处理规则，补CHAMELEON等测试范围，并将raw开发指标与标准测试表分开。当前数据量比官方少也要公开，而不能把383开发集数字与论文测试集混排。

本次没有提供新的性能实验指标，因为没有运行新模型；所有数量、重复与GT差异均来自只读数据检查，不是一次新的分割性能实验。
