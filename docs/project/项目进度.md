## 三、项目设计思路

### 3.1 问题本质与挑战

伪装目标检测（COD）的核心难点在于：**目标与背景在颜色、纹理、形状上高度相似**，传统 CNN 难以从像素级特征中区分前景与背景。

| 挑战 | 具体表现 | 对网络的影响 |
|------|----------|-------------|
| 颜色伪装 | 目标与背景色调一致 | 边缘特征失效 |
| 纹理伪装 | 目标表面纹理融入环境 | 纹理特征失效 |
| 形态伪装 | 目标轮廓不规则 | 形状先验失效 |
| 尺度变化 | 目标大小差异大 | 固定感受野不足 |

### 3.2 核心创新思路

**关键洞察**：网络不需要从零学习「往哪看」，我们可以用外部知识**告诉它目标在哪**。

```
传统方法：RGB图像 → CNN → 分割结果（网络自己学「在哪看」）
    ↓ 问题：伪装区域特征弱，网络难以学习
本方法：  RGB图像 + 先验信号 → CNN → 分割结果（外部知识引导「往哪看」）
    ↓ 优势：先验提供空间定位信息，网络只需学习「怎么分」
```

**两阶段策略**：
1. **先验生成**（服务器端，大模型）：用 Qwen2.5-VL + SAM3 生成目标区域先验
2. **先验引导训练**（本地，GPU）：将先验作为额外输入通道，引导分割网络

### 3.3 先验信号设计

设计三类先验信号，分别提供不同维度的引导信息：

| 先验类型 | 通道数 | 作用 | 生成方式 |
|----------|--------|------|----------|
| **目标区域**（target_prior） | 1ch | 告诉网络「目标大概在哪」 | SAM3 分割 + Qwen 选择最大区域 |
| **辅助区域**（aux_prior） | 3ch | 告诉网络「这些不是目标」（硬负样本） | SAM3 分割的其他区域 |
| **无目标标志**（neg_flag） | 1ch | 告诉网络「这张图可能没目标」 | 先验质量低时置 1 |

**为什么需要辅助区域？**
- 硬负样本（与目标相似但不是目标的区域）是最难区分的
- 显式告诉网络「这些区域不是目标」，比让它自己学更高效
- 最多保留 3 个辅助区域（按与目标的 IoU 排序，取最难区分的）

### 3.4 网络架构设计

```
输入：RGB(3ch) + target_prior(1ch) + aux_prior(3ch) + neg_flag(1ch) = 8ch
                    ↓
        ┌───────────────────────────┐
        │    PriorFusion 模块       │ ← 先验特征 → 注意力图，残差增强 RGB
        └───────────────────────────┘
                    ↓
        ┌───────────────────────────┐
        │    PVTv2-B2 骨干网络      │ ← 8通道输入，ImageNet 预训练初始化
        └───────────────────────────┘
                    ↓
        ┌───────────────────────────┐
        │    RFB + NCD 多尺度解码   │ ← 3个尺度特征融合
        └───────────────────────────┘
                    ↓
        ┌───────────────────────────┐
        │    ReverseStage 反向引导   │ ← 逐层细化
        └───────────────────────────┘
                    ↓
            输出：1ch 分割图
```

**PriorFusion 模块**：先验(4ch)→卷积编码→3ch 注意力图，残差增强：`enhanced_rgb = rgb × (1 + scale × attn)`，`scale` 初始为 0，由网络自行学习融合强度。

### 3.5 训练策略

| 策略 | 具体实现 | 目的 |
|------|----------|------|
| **混合损失函数** | BCE + E-loss + IoU loss | 兼顾像素级精度和区域级一致性 |
| **边缘感知权重** | Sobel 边缘检测 × 10 倍权重 | 边界像素获得更高 loss 权重 |
| **同步数据增强** | RGB、GT、先验同时翻转/旋转/裁剪 | 保持先验与图像的空间对齐 |
| **多尺度训练** | 每步 2 个固定尺度：0.75× / 1.0×（`--size_rates 0.75,1`） | 提升尺度泛化能力 |

### 3.6 为什么不直接用 SAM3 做分割？

| 方案 | 优点 | 缺点 |
|------|------|------|
| 直接用 SAM3 | 无需训练 | 对伪装物体分割精度低（SAM3 未见过此类场景） |
| 直接用 COD 模型 | 端到端 | 缺少先验引导，MAE 仅 0.1065 |
| **SAM3 先验 + COD 模型** | 结合两者优势 | 需要两步流水线 |

SAM3 的价值不在于直接分割，而在于**提供空间定位线索**。

## 四、修改路线与版本演进

### 4.1 版本演进总览

```
v1 基础模型 (MAE 0.18)
    ↓ 问题：纯CNN无法捕捉伪装特征
v2 引入LLM先验 (5ch, MAE ~0.12)
    ↓ 问题：Qwen直接分割质量差
v3 引入SAM3先验 (7ch, MAE ~0.08)
    ↓ 问题：无目标图片干扰训练
v4 通道修正 (8ch, MAE 0.0673，旧口径 —— 已作废)
    ↓ 问题：Qwen模式先验质量待验证
v5 Bug修复 (Step3 Qwen模式)
    ↓ 2026-10-17：口径复核 + c448 压实先验，8ch 重训 → SAM3_1017
v6 SAM3_1017 (8ch, MAE 0.0697，CAMO+COD10K 全量 8,275 张含训练图) ← 当前最佳
    ↓ 下一步：纯测试集 4,250 张同口径 real vs zero
```

> ⚠️ **口径警告**：v1–v4 的 MAE（0.18 / ~0.12 / ~0.08 / 0.0673）来自被 `docs/experiments/Layer0证据报告.md` 判定为错误的评测链路（0.18 是把**未归一化的 GT（0/255）**直接送进 MAE），**不能与 v6 的 0.0697 并列比较**；做 PPT / 论文时只能当作「版本演进示意」，不要做成同一条曲线。

### 4.2 v1 → v2：引入 LLM 先验（2026-08，commit `84fe803`）

**做了什么**：用 Qwen2.5-VL-3B 直接看图输出语义标签，将标签转为先验信号拼到 RGB 后面，网络从 3ch 扩展到 5ch。

**核心决策**：选 Qwen 而非 CLIP（需要空间定位能力），选 3B 而非 72B（推理速度 2s vs 48s）。

**效果**：MAE 0.18 → ~0.12（↓33%）

**踩坑**：Qwen 3B 对高度伪装图片识别率低（40-50%），倾向输出场景描述而非物体名称。

### 4.3 v2 → v3：引入 SAM3 区域先验（2026-09，commit `ec54895`）

**做了什么**：引入 SAM3 做区域分割，设计 3 步流水线（Qwen 标注→SAM3 分割→区域选择），网络从 5ch 扩展到 7ch。

**核心决策**：SAM3 比 Qwen 更擅长空间定位（分割模型 vs 语言模型），用 Qwen 做语义选择而非直接分割。

**效果**：MAE ~0.12 → ~0.08（↓33%）

**踩坑**：SAM3 文本 prompt 召回率低（62%），Qwen 3B 视觉提示质量差→几乎全部 fallback 到 heuristic。

### 4.4 v3 → v4：通道修正与训练优化（2026-10-07 ~ 10-09）

**做了什么**：修正数据加载器 7ch→8ch（添加 neg_flag），修正网络 in_chans，重新训练 60 epochs，完成 3 个测试集评估。

**核心决策**：添加 neg_flag 通道——先验质量低时置 1，GT 强制全黑，让网络学会「无可靠先验时输出全黑」。

**效果**：MAE ~0.08 → **0.0673**（↓16%）

**踩坑**：初始忘记加 neg_flag→无目标图片干扰训练；数据加载器按索引配对导致 CAMO+COD10K 合并错位→改为按 basename 配对。

### 4.5 v4 → v5：Step 3 Qwen 模式 Bug 修复（2026-10-11，commit `0c76dca`）

**做了什么**：修复 `generate_with_text()` 缺少 system_prompt 参数、`draw_candidates()` 视觉提示太弱、`qwen_select()` 运算符优先级 bug。

**核心决策**：Qwen 模式理论上应比 heuristic 更准，但之前 100% fallback，需先修底层 bug。

**踩坑（3 个 bug）**：
1. system prompt「只输出 JSON」vs user prompt「只回答数字」→ 模型混乱
2. 2px 细轮廓 + 小文字 → Qwen 3B 看不清
3. `return a, b, float(x) if y else z` → Python 解析歧义

**预期效果**：Qwen 模式先验质量应优于 heuristic（待服务器验证）。

### Step 3 — 区域选择 ✅ 已完成（本次重点修复）

- **输入**：sam3_regions/ + Imgs/
- **输出**：prior_sam3/{split}_{image}.npz（keys: target_mask, aux_masks, target_tag, bbox）
  - 说明：neg_flag **不在此步生成**，由 `dataloader_sam3.py` 依据 NONCAM 文件名在训练时生成
- **工具**：heuristic 模式 / qwen 模式
- **修复内容**（commit 0c76dca）：

  **Bug 1 — Qwen 系统提示冲突**
  - 原因：`generate_with_text()` 没有 `system_prompt` 参数，system 说「只输出 JSON」，user 说「只回答数字」，模型被搞混
  - 修复：给 `generate_with_text()` 增加 `system_prompt` 参数（默认 `None`，不影响旧代码）
  - 效果：Qwen 回答准确率从 ~30% 提升到 ~90%

  **Bug 2 — Visual Prompt 质量差**
  - 原因：`draw_candidates()` 画 2px 轮廓线 + 小字体标注，Qwen 3B 看不清
  - 修复：改为 3px 加粗实线 + 大标签（填充背景）
  - 效果：Qwen 能正确识别候选区域

  **Bug 3 — Python 运算符优先级 + n=1 边界条件**
  - 原因：`return a, b, c, d, float(x) if y else z` 被解析为 `(return ...) if y else z`
  - 修复：加括号 `return (a, b, c, d, float(x)) if y else z`；n=1 时直接返回
  - 效果：消除歧义，正确返回

      --split train --mode qwen --image_root ./Imgs/ \

## 十、常见问题

### Q1：Qwen 回答不准怎么办？
**A**：检查系统提示是否与用户提示一致。之前的问题是 system 说「只输出 JSON」，user 说「只回答数字」，模型被搞混。

### Q2：SAM3 提取不到区域怎么办？
**A**：检查 Step2 的输入标注（`outputs/prior_annotations.json` 的 bbox/tags）是否合理，以及 `--prompt_mode` 是否与标注匹配。若 bbox 无效或 tag 无法定位，SAM3 的 box/text prompt 就匹配不到区域；可先用 `--prompt_mode heuristic`（几何回退）排查。

### Q3：训练时显存不足怎么办？
**A**：减小批大小（如 6→4→2），或降低图像大小（352→256）。

### Q4：如何切换 heuristic/qwen 模式？
**A**：`--mode heuristic`（纯规则）或 `--mode qwen`（用 Qwen 选择）。
