# 基于粗掩码引导文本的 COD：E0–E4 免训练验证执行方案

**日期**：2026-10-20<br>
**性质**：可交给 Codex/项目作者实施的实验任务书；本文件不代表实验已执行<br>
**代码依据**：用户提供的 `share_sam3_20261017.zip`、`README.md` 以及《Concealed Object Detection》（Fan 等）。

## 0. 本轮研究问题与边界

**核心问题 A**：视觉 COD 粗预测 `M0` 能否让 Qwen2.5-VL-3B 生成更准确、更少幻觉的目标语义？对应 **E3 vs E2**。

**核心问题 B**：由 `M0` 得到的框提示 + 区域感知文本提示，能否使 SAM3 的预测优于仅用框提示？对应 **E4 vs E1**。

**辅助问题**：SAM3 的框提示细化是否优于原始视觉预测？对应 **E1 vs E0**。文本分支单独的能力如何？对应 E2、E3。

**范围严格限制**：本轮只运行已有模型的推理；不训练、微调、反向传播、修改 checkpoint；不利用 GT、类别标注、文件名中隐含的标签或 `NonCAM` 标记来生成/过滤任何模型提示；不接入原 8 通道网络做主实验；不覆盖任何已有模型或历史结果。GT **只能**在全部预测已落盘后用于评估、分层统计和人工复核。

**条件**：分享 ZIP 只有源码与文档，没有数据集和模型权重，实际运行需要项目作者在服务器上核验并提供原三通道 PVTv2 COD 权重、Qwen2.5-VL-3B 权重、SAM3 权重及对应数据。任一缺失应 `BLOCKED`，不可用随机权重或旧 7/8 通道权重代替。

## 1. E0–E4 严格定义

| ID | 视觉首轮 M0 | 交给 Qwen 的内容 | 交给 SAM3 的提示 | 最终输出 | 核心比较 |
|---|---|---|---|---|---|
| **E0** | 3ch 冻结 RGB baseline 推理 | 无 | 无 | M0 | 视觉参考 |
| **E1** | 同一份 M0 | 无 | M0 连通域生成的框；逐框独立推理 | `M_box` | E1 vs E0：几何细化 |
| **E2** | M0 仅用作缺失结果时统一回退，不参与正常提示 | **原始 RGB** | Qwen 的英文简短文本；逐条独立推理 | `M_text_rgb` | 纯原图文本路线 |
| **E3** | 同一份 M0 | **原 RGB + M0 半透明/轮廓图 + 保留上下文的 ROI 拼图** | Qwen 的英文简短文本；不加入框 | `M_text_mask` | E3 vs E2：区域引导文本 |
| **E4** | 同一份 M0 | 复用 **E3** 的 Qwen 文本，不再次生成 | 复用/独立生成 E1 框候选和 E3 文本候选，做固定非 GT 一致性融合 | `M_fused` | E4 vs E1：文本增量；E4 vs E3：几何增量 |

注意：E4 **不是**直接沿用 `sam3_regions.py --prompt_mode hybrid`。当前源码的 hybrid 在框分支成功时会跳过与主框同名的文本 prompt，因此可能实际没有“两条分支”。新实现要能证明 `BOX_EXECUTED` 与 `TEXT_EXECUTED` 均按计划发生，并隔离提示状态，避免一次调用残留的 state 影响另一次。

### 1.1 E0：视觉模型推理基准

- 选择 `Network_PVTv2.Network(channel=64, imagenet_pretrained=False)`，加载对应 **3 通道**权重；检查 patch_embed1 首层形状、模型全部 state_dict 键及形状，严格加载，不接受静默部分加载；记录 SHA-256、训练来源/训练集来源和 checkpoint 选取依据。
- 使用与现有推理一致的 RGB 预处理：缩放至 352×352、ToTensor、ImageNet normalize，读取原始图像尺寸；取网络第四个返回值（即现有 `MyTest.py` 使用的 `cam_out_4`/`S_3_pred`），插值回**原图尺寸**后 sigmoid。
- 保存 `[0,1]` 浮点概率图 `M0_soft.npy` 和可视化 PNG；**不得**做逐图 min-max 拉伸。为公平比较，同时以统一 `p >= 0.5` 保存 `M0_binary.png`。任何用于 SAM3/Qwen 的 ROI、框从 `M0_soft` 派生。
- 新建无 GT 依赖的推理入口。原 `MyTest.py` 只跑 CAMO、用 GT 获取 resize 尺寸、默认逐图 min-max；不能原封不动作为此次唯一 E0 生成器。GT 不进入推理过程。

### 1.2 从 M0 提取空间 ROI 的统一规则（预注册起点）

- 先以固定 `threshold = 0.5` 二值化；求 8 连通域；去掉面积 `< max(24 px, 0.0005×HW)` 的微小碎片；按面积降序、同面积按左上角坐标排序，最多保留 3 个区域；**不能**按 GT 正确与否排序。
- 每个区域提取原图坐标轴对齐 bbox，四边各扩大该框相应宽/高的 12%，裁剪到图像边界；不得将不同物体的框坐标取平均。
- 生成 Qwen 区域拼图：左侧原 RGB，中间仅叠加半透明轮廓/遮罩（不抹掉 RGB 纹理），右侧展示最多 3 个 ROI 裁剪（应带 12% 上下文）；编号与 JSON 记录对应，所有坐标变换可逆。
- `M0` 无有效连通域时：E1 无框，记录 `NO_ROI`；E3 **复用 E2 的原图文本及其 SAM3 文本候选**，不假造 ROI，记录 `E3_FALLBACK_E2`；E4 按事先固定的缺失处理规则工作。不能根据数据集名称、GT 是否全黑改变行为。

### 1.3 E2/E3：Qwen 描述生成

- 使用同一个 Qwen2.5-VL-3B checkpoint、相同 system instruction、`do_sample=False`、相同最大输出 token、同一段英文 JSON schema；单图 **各最多 1 次 Qwen 调用**。E2 输入原图；E3 输入区域拼图；除了图片内容，不进行数据集相关的 prompt 定制。
- 建议 schema：`{"objects":[{"name":"frog","sam_text":"a mottled brown frog","region_id":1}],"uncertain":false,"no_visible_object":false}`，最多 3 项。`region_id` 对 E2 可以是 `null`。模型需要允许 `{ "objects": [], "uncertain": true }`。
- 指令强调“区域高亮来自可能错误的视觉预测，不是 GT；不要仅凭颜色/轮廓猜类别；只描述肉眼可见的目标；无确证时输出空列表；每条 `sam_text` 为简短英文名词短语（建议 1–6 个词），不写场景长句和坐标。”
- 输出原始 Qwen 回答、解析后 JSON、解析状态、无目标/未知状态、实际用于 SAM3 的文本列表及校验原因。解析失败可以固定重试 1 次，但 E2/E3 重试规则一致，次数写日志。不能让人工现场修改单张图的 prompt 再纳入主结果。
- **禁止**使用 `llm_annotator.extract_context(filename)`：该函数会从 COD10K 文件名中推断类别，造成标签泄漏。可以复用 `generate_with_text` 的模型调用能力，但应新建无文件名上下文的 wrapper 并校验 JSON。`is_noncam_name` 只允许在**评估阶段**分层，不允许影响 Qwen/SAM3 是否运行。

### 1.4 E1/E2/E3：SAM3 输出与一致性

- **所有 SAM3 分支始终输入原始 RGB**，不是 Qwen 看到的轮廓/拼图，也不是只有黑白 Mask 的图。
- E1 使用 `Sam3Processor.add_geometric_prompt(box=normalized_xywh, label=True, state=...)`。在原图尺度构框、规范化为 `[cx/W,cy/H,w/W,h/H]`，核验边界合法性；对最多 3 个框分别提示。
- E2/E3 用 `Sam3Processor.set_text_prompt(prompt=...)`，最多 3 个互不重复的短文本。每条文本须独立初始化/重置提示 state，不能残留上一次框/文本结果；验证独立运行与批量运行的一致性。
- SAM3 checkpoint 和默认置信阈值先保持源码配置（`confidence_threshold=0.5`）。每个提示保存全部候选、分数、空结果及实际执行状态；预注册以每条提示的最高分候选作为该条结果（不根据 GT 选择），多提示结果做并集得到图像级 Mask。
- 缺少任何 SAM3 有效输出时，**E1–E4 一律回退到 `M0_binary`**，并记录 `FALLBACK_E0`；E3 无 ROI 时回退文本生成路径 E2 并记录。在“含回退的端到端表现”之外，另报 SAM3 有效覆盖率、纯 SAM3 成功子集上的指标；不得只拿成功子集跟 E0 全集比较。
- 产出在原图分辨率上的 `uint8` Mask（0/255），另外保留 SAM3 原始有效概率/候选（如 API 可用），避免只有最终二值图无法溯源。

### 1.5 E4：无需训练的**固定**双路融合规则

主规则在看正式结果前固定，不允许按 GT 逐图选最好的那张 Mask。**E4 读取的是 E1/E3 的原始 SAM3 候选（含有效性标记），不是它们可能已经回退到 M0 的最终结果图**，否则会把回退误当作有效框/文本证据：

1. 若框分支与文本分支都有非空候选，计算候选两两 Mask IoU（只来自预测）。匹配阈值起点 `0.30`。
2. 对每个匹配对 `(B,T)`，保留框候选 `B`，只加入文本候选落在 `dilate(B,r)` 内的补充像素：`R = B ∪ (T ∩ dilate(B,r))`。建议 `r = round(0.05×max(bbox_w,bbox_h))`，具体实现保留边界裁剪与单元测试。不同区域的 `R` 再并集。
3. **没有匹配的文本候选**先不自动补入（避免误检扩张），但完整保存作后续漏检分析；没有匹配的框候选原样保留。如果只有文本结果而没有任何框结果，则使用文本结果；如果只有框结果，使用框结果；二者都没有，则回退 M0_binary。
4. 输出 `matched_pairs`、`unmatched_text`、`unmatched_box`、`added_pixel_ratio` 等诊断字段。`score` 不当作校准置信度。

该规则是**诊断起点**而非已验证最优融合策略。它偏保守，可能放弃正确但远离粗预测的第二个目标；必须单列“文本提出的新目标被拒绝”的失败案例，不得据此笼统认定文本无用。

## 2. 评估分母与抽样

**P0 / CPU+少量 GPU 流程预检**：从具备可访问权重与数据的开发样本中固定抽 30 张（建议 CAMO 风格、COD10K-CAM、COD10K-NonCAM 各 10 张，必要时用训练图仅检查流程）。只用于可运行性、可视化与解析检查，不作方法优劣结论。保证首轮计算 GT 不传给推理代码。

**P1 / 首个免训练对照**：在开始前写死 `image_manifest.csv`，使用随机种子 20261020，从**未用来修改提示设计的测试数据**分层选择 200 张，起点建议 CAMO 50、COD10K-CAM 100、COD10K-NonCAM 50；实际需从原始数据索引和 GT 完整性核对数量。每组固定同 200 张，不因失败而替换。

**P2 / 扩展与确认（需根据 P1 审阅再启动）**：配置、阈值、prompt、融合算法和代码 hash 固定后，对其余未使用测试图运行。依当前项目 README，完整测试范围名义为 CAMO 250 与 COD10K 4000，其中 COD10K-CAM 2026、COD10K-NonCAM 1974；务必以实测文件名单核对。主表分别报告 **CAMO、COD10K-CAM**；NonCAM 作为独立负样本表。不能用混合训练图的 0.0697 作正式泛化对照。若 P1 结果曾用于选 prompt/阈值，则 P1 只能标为 exploratory，P2 未参与选择的图才用于确认性结论。

**主指标**：S-measure ↑、**mean E-measure** ↑、weighted F-measure ↑、MAE ↓，单图宏平均；附图像级 IoU、Dice、精确率/召回率、前景面积偏差作为诊断。现有 `eval_metrics.py` 显示的 `Ephi` 来自 `adpem`，不是 meanE，须修正指标口径并单独保留 adpE。所有组应用同样 resize、GT 二值阈值、库版本及非有限值处理。评价脚本发现任何 missing/duplicate ID、尺寸/通道不符或非有限值必须 `HOLD`，不能静默用交集改变分母。

**二值公平比较**：SAM3 常给出二值候选，主对照可用 `E0_binary` 与 E1–E4 的二值掩码统一计算四指标；另外对 `E0_soft` 报告标准连续预测 COD 指标，**不能混淆 E0_binary 与历史 min-max 的 E0**。如果 API 有可靠的逐像素概率输出，再增加连续预测附表，不改变主表规则。

**文字质量评估**：P1 预先随机选择 60 张（CAMO/COD10K-CAM/NonCAM 均覆盖），匿名打乱 E2/E3 文字；独立查看原图与 GT 后记录类别正确、形态/纹理可见性、凭空编造、漏掉其他目标和正确 abstain；只用于**事后分析**，不反馈到本轮提示生成。主要关注 E3 对 E2 的差异和 NonCAM 的幻觉率。

## 3. 源码具体改动（只新增独立模块）

**不要**运行 `run_server_pipeline.py` 全流程：当前脚本包含训练、清理与历史先验生成逻辑。本实验实现为独立 `tools/e0e4/`，默认只读模型和数据、只向指定新 `--out` 目录写入。

建议新增：

- `tools/e0e4/preflight.py`：检查数据/路径/GPU、三个 checkpoint SHA-256、3ch 验证、sam3 API 调用、目录安全和磁盘容量。
- `tools/e0e4/build_manifest.py`：生成严格唯一的图片 ID、split、原图文件 hash、尺寸、GT 独立路径；生成 P0/P1/P2 固定名单，运行阶段不把 GT/类别等字段传入 prompt 构建器。
- `tools/e0e4/infer_e0.py`：从 `Network_PVTv2` 输出 raw sigmoid soft+binary，校验严格加载，不依赖 `test_dataset` 加载 GT 尺寸。
- `tools/e0e4/roi_from_mask.py`：实现 8 连通域、bbox padding、坐标转换、透明覆盖、ROI 拼图和单元测试。
- `tools/e0e4/caption_qwen.py`：生成 E2/E3 的文本与 JSONL；禁止 filename/category/context 泄漏；实现相同 Qwen 配方与缓存 hash。
- `tools/e0e4/segment_sam3.py`：E1 框、E2/E3 文本的独立 state 推理；结构化失败原因；输出候选与分数。
- `tools/e0e4/fuse_e4.py`：固定非 GT 双路融合，不以 `region_selector.py` 的目标挑选启发式作为本次主方案。
- `tools/e0e4/eval_strict.py`：读取固定 manifest，硬检查 5 组完整性；统一主四指标和逐图 delta。
- `tools/e0e4/make_review.py`：统计覆盖/错误/耗时/方法差异，生成代表性可视化和人工复核名单。
- `configs/e0e4_v1.yaml`：冻结所有超参数及 prompt 模板版本。

## 4. 实际执行顺序与阶段门

1. **Gate A：只读审计和设计确认。** 核验 3ch baseline、Qwen、SAM3 权重和数据文件，留存版本/hash/来源；生成 manifest 与预注册配置，给出资源预估。缺任一关键权重/数据立刻 BLOCKED。
2. **Gate B：纯 CPU 单元测试。** 测坐标转换、多个目标/极小目标/空 Mask/全图 Mask、Qwen JSON 解析、同名冲突、缺图与指标非有限值；验证运行前没有 GT 数据流。
3. **Gate C：P0 30 张小样本全链路。** 顺序执行 E0→ROI→E2/E3 Qwen→E1/E2/E3 SAM3→E4 非 GT 融合→事后评估。保留逐图耗时及显存峰值，测出实际图/秒，再估 P1/P2 工时。先小规模顺序运行 Qwen 与 SAM3，避免显存互相抢占。
4. **Gate D：冻结配置，P1 200 张推理。** 五组使用相同图像名单；不重复采样、不人工调整单图 prompt、不自动修改阈值；失败路径明示回退和计数。
5. **Gate E：证据审阅。** 输出四主指标、配对逐图差值与置信区间、文字质量、候选覆盖、非 CAM 幻觉、失败类型、图卡。允许结论为 `NO_EVIDENCE` 或 `MIXED`。
6. **P2 暂不自动执行**。先提交 P1 报告供研究者审阅；如果准备做正式测试，锁定配置并在未用于调参的数据上确认。

**最低通过条件**：所有输入图片映射到且仅映射到一份 E0–E4 预测；`Qwen E2/E3` 成功/失败均有原始日志；SAM3 box/text 真正运行次数可审计；E4 不访问 GT；指标是同分母；权重 hash 未改变；没有触发 `optimizer.step`/training；出现缺图、无效权重、预测污染、数据泄漏时状态 HOLD，禁止填写性能结论。

## 6. 结果判读 / 下一步决策

| 观察 | 推断范围 | 下一步 |
|---|---|---|
| E3 描述准确性/幻觉率优于 E2，但 E3 分割无提升 | 区域指引有助于语言，但文本到 SAM3 的接口未发挥收益 | 排查短文本适配、SAM3 提示粒度、候选选择 |
| E3 与 E2 文字相似，分割也相似 | 首轮粗 Mask 未明显帮助描述 | 检查 M0 质量、ROI 保留上下文、Qwen 是否真正关注标注区域 |
| E1 > E0，E4 ≈ E1 | 几何细化已有收益，暂未证明独立文本增益 | 不应直接声称“文本改善分割”；可以追加 generic/wrong-text 控制 |
| E4 > E1，E3 > E2，且改善跨 CAMO/COD10K-CAM 稳定 | 支持区域感知语言辅助分割的研究假设 | 再考虑训练轻量文本模块和可靠性分支 |
| E4 结构更完整，但 MAE/weighted F 下降 | 文本扩张可能引入 FP | 分析新增 TP/FP/漏检，先改融合规则而不是盲目继续训练 |
| NonCAM 幻觉和 FP 显著 | 文本提示存在背景误认风险 | 增加独立的语义拒绝与视觉证据校验（作为下一轮假设） |

**注意归因**：E2→E3 同时改变了视觉输入呈现（标记 + ROI 裁剪），因此若 E3 改善，结论应表述为“粗 Mask 引导的区域感知输入改善了自动文本”，不能直接归因于二值轮廓本身。如需再分解，可追加 `RGB+相同 ROI 裁剪但无轮廓` 作为后续控制，不计入本轮 E0–E4 主表。
