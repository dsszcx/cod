## 1. 项目定位与当前结论

**做什么**：用 SAM3 + Qwen2.5-VL-3B 自动生成"目标区域 + 辅助区域"先验，作为额外通道（8ch = RGB 3 + target 1 + aux 3 + neg_flag 1）喂给 PVTv2-B2 分割网络，在伪装目标检测（COD）上做像素级分割。

**交付了什么**（`[实测]`）：

| 交付物 | 载体 | 状态 |
|:---|:---|:---|
| 可运行的 5 步流水线 | `run_server_pipeline.py`（47,207 B，纯标准库）+ `run_server_pipeline.sh`（1,491 B 薄封装） | 有闸门、有 dry-run、有 `--fresh` 清理 |
| 纯推理对照 E0–E4 | `configs/e0e4_v1.yaml` + `tools/e0e4/` 12 个模块 + `tests/test_e0e4.py` | 本机回归通过；Gate C/D/E 待服务器执行 |
| 训练 / 推理 / 评测 | `MyTrain_SAM3.py`、`MyTest_SAM3.py`、`eval_metrics.py`、`新metric.py` | 含"预测不全就报错"的严格口径 |
| 权重通道审计 | `check_ckpt_channels.py` | 实测：本机 53 个 `.pth` **没有一个是 8ch** |
| 文档 | `文本类/` 18 个文件（含 2026-10-21 恢复的 6 个旧文档） | 本轮新增本文件 |
| 部署包 | 3 个 zip + 3 个 `.sha256` | 见 §3 第 27–32 行 / §7 |

**唯一对外数字 `MAE = 0.0697` 的口径（必须一起讲）** `[文档]`（`README.md`、`docs/project/项目进度.md`、`docs/deployment/分享说明.md` 三处一致）：

- 口径 = **CAMO + COD10K 全部有 GT 的图（训练 CAM 子集 4,040 + 测试集 4,250，名义 8,290，实际参与 8,275）合并算出的一个总 mean MAE**；
- **分母含训练时见过的图 → 偏乐观，不能当泛化精度**；
- 无先验基线 **0.0632 是 CAMO 250 张纯测试集口径 → 两者不可直接比较**，"先验是否有效"目前**没有结论**；
- 旧记录 **"MAE 0.0673 / 相对 0.18 提升 63%" 已作废**：0.18 是把未归一化 GT（0–255）送进 MAE 得到的"前景占比×255"，与预测好坏无关（`docs/experiments/Layer0证据报告.md`）；
- 该权重 `model_pth/SAM3_1017/` **只在服务器**，本机 `model_pth/` 下不存在该目录（`[实测]`，本机只有 `OUR/ SAM3/ SAM3_ALL/`）。

> 结论一句话：**这套代码今天的价值是"可复现、可诊断、带闸门的完整流水线"，不是"已经刷出 SOTA"**。精度结论要等 §5.2 的 E0–E4 同口径对照跑完。

**三个必须知道的结论**：

1. **本机没有任何 8ch 权重**（0 个）。7ch = RGB + target + aux×3（v3 网络）；当前 `Network_SAM3` 是 8ch（多一个 `neg_flag`），直接加载会报
   `size mismatch for backbone.patch_embed1.proj.weight: [64,7,7,7] vs [64,8,7,7]`（`check_ckpt_channels.py` docstring 实测记录，样例 `SAM3/KKK_best_41.pth`）。
2. **`OUR/log.log` 的 "best" 不可信**：打印 `MAE=46.076…`、`Best Epoch: 0`；46.076/255 = 0.1807 正好是 CAMO 测试集前景占比，说明是"GT 0–255 vs 预测 0–1"的口径错误。因此 E0 预注册用 `Net_epoch_40.pth`（训练终点，规则可写死），而不是日志里的 best。
3. **`model_pth/SAM3_1017/`（产出 0.0697 的那批权重）只在服务器**，本机不存在（`[实测]` 本机仅 3 个子目录）。

> 另：`model_pth/OUR/*.pth` 只有 **740 个 key**，当前 `Network_PVTv2`（GRA 内新增 `ChannelAttention`）需 758 个；缺的 18 个是 `RS*.{weak,medium,strong}_gra.ca.fc.*`。所以 E0 必须 `use_ca=False` 才能 740/740 严格加载，否则 18 层 CA 会被随机初始化而无人察觉。

### 11.2 指标口径（写论文/PPT 前必读）

| 指标 | 实现位置 | 本项目口径要点 |
|:---|:---|:---|
| MAE | `新metric.py` `GrayscaleMetricRecorderV2` | 预测与 GT **都必须先归一化到 [0,1]**；0.18 那个旧值就是把 0–255 的 GT 直接算进去的产物 |
| Sα（S-measure） | 同上 | 自适应权重版本；调用方不得自行改阈值 |
| mean E / adp E | 同上 | 本项目同时记录 fixed 与 adaptive 两列，报数时必须说明用的是哪一列 |
| Fβw | 同上（`eval_metrics.py` 输出为 `Fβw`） | 加权 F，β²=0.3；旧文档里各种 F 列写法口径不明，**禁止与新结果混表** |
| adpF1 / adpIoU / adpDice | `eval_metrics.py`、`tools/e0e4/eval_strict.py` | 只在 E0–E4 的 strict eval 里使用 |
| 分母 | `eval_metrics.py` | 缺预测图/多图直接抛 `ManifestError`，**不允许**通过丢失样本来抬高分数 |

> 两条硬规则：① 任何 MAE 必须带"N=多少张、哪几个数据集、是否含训练图"；② 不同口径的数字不放进同一张表。

### 11.3 术语表

| 术语 | 含义（本项目内） |
|:---|:---|
| 先验 / prior | 训练时拼在 RGB 后面的辅助通道（target 1 + aux 3 = 4 通道） |
| 8ch | RGB(3) + target(1) + aux(3) + neg_flag(1)，`Network_SAM3` 当前输入 |
| neg_flag | 先验不可靠/无目标=1，GT 强制全黑，教网络"没先验就输出黑" |
| ROI / M0 | Layer-2 里"二值先验 → 框 → 裁剪 → 拼图"的中间产物；**M0_binary 不参与最终分割**，净效应记作 E4−E3 |
| c448 | 先验压缩到 448×448 uint8（`tools/compact_priors.py`），78 GB → 0.3 GB |
| P0 / P1 | 对照实验样本集：P0 = 30 张（10/10/10），P1 = 200 张（50/100/50，seed 20261020） |
| Gate A–E | 五道闸门：A 代码回归、B 环境、C 30 张冒烟、D 200 张、E strict eval |
| guards | `configs/e0e4_v1.yaml` 里六条防 GT 泄漏开关，**必须全 false** |
| E0–E4 | 五个对照分支（都**不读 GT**）：E0 = 冻结 3ch 基线 `Net_epoch_40.pth`；E1 = 用 E0 的 `M0_binary` 出 ROI 做 SAM3 框提示；E2/E3 = Qwen→文本→SAM3（原图 / 三栏拼图）；E4 = E1 与 E3 的固定规则融合，无匹配回退 E0 |
