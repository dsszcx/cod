# 📘 项目文档 — SAM3 先验引导伪装目标检测

> 更新日期：2026-10-14

---

## 一、项目概述

**伪装目标检测（Camouflaged Object Detection, COD）**：输入图片，输出**像素级分割掩码**（白=伪装目标，黑=背景）。

### 核心创新

用大模型（Qwen2.5-VL-3B）和 SAM3 生成"目标区域+辅助区域"先验，引导分割网络，显著提升伪装目标分割精度。

**核心成果**：⚠️ 曾报告 MAE 0.0673（相对基础模型 0.18 提升 63%），但**本地无法复现**（缺 `prior_sam3/` 与评估日志），**待重新验证**。

### 网络结构

- 骨干：PVTv2-B2（ImageNet 预训练）
- 8通道输入：原图(3ch) + 目标先验(1ch) + 辅助先验(3ch) + 负样本标志(1ch)
- 损失函数：Hybrid E-loss
- 推理输出：1ch 二值分割图


## 四、运行命令

### Step 1：Qwen 预筛选标注（服务器 cx2）

```bash
# prescreen 模式（推荐，适合 3B 小模型）—— OpenCV 检测候选 + Qwen 命名
python llm_annotator.py --data_root ./Imgs/ --split train --mode prescreen \
    --model /opt/models/Qwen2.5-VL-3B-Instruct/ \
    --out outputs/prior_annotations.json

# legacy 模式（原始开放式问答）
python llm_annotator.py --data_root ./Imgs/ --split train --mode legacy \
    --model /opt/models/Qwen2.5-VL-3B-Instruct/ \
    --out outputs/prior_annotations.json

# 多 GPU 并行
python llm_annotator.py --data_root ./Imgs/ --split train --gpus 0,1,2 \
    --out outputs/prior_annotations.json

# 只处理特定图片列表（如 COD10K CAM 子集）
python llm_annotator.py --data_root ./COD10K-v2/COD10K-v2/Train/Image/ \
    --split train --filelist ./COD10K-v2/COD10K-v2/Info/CAM_train.txt \
    --out outputs/prior_annotations.json

# 断点续跑（默认开；只补缺失的图，不会重跑已有条目）
python llm_annotator.py --data_root ./Imgs/ --split train --out outputs/prior_annotations.json
python llm_annotator.py --data_root ./Imgs/ --split test  --out outputs/prior_annotations.json
```

**关键参数：**

| 参数 | 说明 | 默认值 |
|:---|:---|:---|
| `--mode` | `prescreen`（推荐）或 `legacy` | `prescreen` |
| `--box_fallback` | 显著性没找到候选框时的兜底：`quad`=整图+四象限、`whole`=仅整图、`off`=回落开放式提问（旧行为） | `quad` |
| `--noncam_policy` | COD10K NonCAM（GT 全黑、无目标）处理：`skip_train`=训练集跳过、`skip_all`=两个 split 都跳过、`annotate`=照旧标注 | `skip_train` |
| `--gpus` | 多 GPU，逗号分隔 | `0` |
| `--num_runs` | 多轮标注投票次数 | `1` |
| `--filelist` | 只处理列表内的文件名 | 无（处理全部） |
| `--max_images` | 限制图片数（调试用） | `-1`（全部） |
| `--no_resume` | 关闭断点续跑（重跑全部） | 关（即默认 resume） |

一次性编排入口对应参数：`run_server_pipeline.py --ann_box_fallback {quad,whole,off}`、`--noncam_policy {skip_train,skip_all,annotate}`（Gate1 的分母会自动用剔除 NonCAM 后的数量）。

**产出**：`outputs/prior_annotations.json`（格式见下方数据格式节）

### Step 2：SAM3 区域生成（服务器 cx1）

```bash
# box-prompt 模式（推荐，使用 LLM 标注的 bbox 作为框提示）
python sam3_regions.py --data_root ./Imgs/ \
    --ann outputs/prior_annotations.json --split train \
    --ckpt ./sam3-main/sam3-main/checkpoints/sam3.pt --out ./sam3_regions/ \
    --prompt_mode box

# text-prompt 模式（原始行为，使用 tag 文本提示）
python sam3_regions.py --data_root ./Imgs/ \
    --ann outputs/prior_annotations.json --split train \
    --ckpt ./sam3-main/sam3-main/checkpoints/sam3.pt --out ./sam3_regions/ \
    --prompt_mode text

# hybrid 模式（box 优先 + text 补充）
python sam3_regions.py --data_root ./Imgs/ \
    --ann outputs/prior_annotations.json --split train \
    --ckpt ./sam3-main/sam3-main/checkpoints/sam3.pt --out ./sam3_regions/ \
    --prompt_mode hybrid
```

**关键参数：**

| 参数 | 说明 | 默认值 |
|:---|:---|:---|
| `--prompt_mode` | `box`（框提示，推荐）/ `text`（文本提示，原始）/ `hybrid`（框+文本） | `box` |

**产出**：`sam3_regions/{split}_{image_stem}.npz`（key: tags, masks, scores, bbox）

### Step 3：Qwen 判别目标/辅助区域（服务器 cx2）

```bash
python region_selector.py --regions ./sam3_regions/ --out ./prior_sam3/ \
    --split train --mode qwen --image_root ./Imgs/ \
    --qwen_model /opt/models/Qwen2.5-VL-3B-Instruct/
```

**关键参数：**

| 参数 | 说明 | 默认值 |
|:---|:---|:---|
| `--mode` | `qwen`（Qwen视觉判别）或 `heuristic`（本地启发式） | `heuristic` |
| `--min_target_ratio` | 目标最小面积比（低于此→零先验） | `0.005` |
| `--conf_thresh` | SAM3 最低置信度（低于此→零先验） | `0.6` |
| `--max_aux` | 最大辅助区域数 | `3` |
| `--draw_dir` | 保存候选标注图目录（便于抽查） | 无（临时目录） |

**产出**：`prior_sam3/{split}_{image_stem}.npz`（key: target_mask, aux_masks, target_tag, bbox）

### Step 4：训练（本地 RTX 4070）

```bash
# 单测试集（CAMO）
python MyTrain_SAM3.py --epoch 80 --batchsize 6

# 双测试集（CAMO + COD10K）
python MyTrain_SAM3.py --epoch 80 --batchsize 6 --test_datasets CAMO,COD10K
```

**产出**：`model_pth/SAM3/` 下的 `.pth` 权重文件

### Step 5：推理（本地 RTX 4070）

```bash
python MyTest_SAM3.py --pth_path ./model_pth/SAM3/KKK_best_41.pth
# 预测图存 results_sam3/<权重名>/<数据集>/
```


### COD10K NonCAM（无目标样本）— 重要

训练集 7000 张 = **CAMO 1000 + COD10K-CAM 3040 + COD10K-NonCAM 2960**。NonCAM 图
按设计就**没有伪装目标**：GT 是整张全黑，第 8 个输入通道 `neg_flag` 也是由文件名
规则推出来的 1。

| 位置 | 规则 |
|:---|:---|
| 单一真相源 | `dataloader_sam3.is_noncam(name)`：`"NonCAM" in os.path.basename(name)`（训练/推理/Web 服务都调用它，避免喂给网络的第 8 通道不一致） |
| Step1 标注 | 默认跳过（`--noncam_policy skip_train`）：没有目标可标注，问 Qwen 只会让它凭空编造 |
| Gate1 分母 | 用剔除 NonCAM 后的 **CAM 子集 4040**（不是 7000）。否则 `--min_ann_ratio 0.30` 相当于只要求 `2100/4040≈52%`，及格线被 2960 张注定拿不到标签的图抬高 |
| Step3/4 先验 | 这些图本就该是「全 0 先验 + neg_flag=1」，属于设计预期，不是缺先验 |
| Gate4 分母 | Step1 跳过 NonCAM 后，Step2/3 只会为 CAM 图产出 npz，因此「全 0 先验占比」的分母≈4040，阈值比按 7000 张算更严 |

回滚开关：`--noncam_policy annotate`（连同 `--ann_box_fallback off`）可完全恢复旧行为。

## 七、效果总结

### 7.1 口径 A：CAMO 250 张纯测试集（基线 vs 旧先验实验）

> ⚠️ **2026-10 更正（Layer-0 复核，详见 `docs/experiments/Layer0证据报告.md`）**
> 旧表里的 “0.18” **不是 MAE**：历史评测代码把**未归一化的 GT（0/255）**直接送进 MAE，
> 算出来的是 “GT 前景像素占比 × 255”（本机复现值 **33.47**，与旧日志的 46.08 同源），
> 与预测好坏无关。下表由 `eval_metrics.py`（唯一指标口径）在
> `results/OUR/CAMO` 与 `results_sam3/SAM3/CAMO` 上重算，**SAM3 没有任何指标提升**：

| 方案 | MAE ↓ | Sm ↑ | Fβw ↑ | adpF1 ↑ | adpIoU ↑ |
|:---|:---:|:---:|:---:|:---:|:---:|
| 基础模型（无先验） | **0.0632** | **0.8351** | **0.7572** | **0.7989** | **0.6939** |
| SAM3 先验模型（旧，先验实为全 0） | 0.0673 | 0.8237 | 0.7467 | 0.7851 | 0.6776 |

> 第二行那次的先验实际是死分支（`prior_sam3/` 不存在 → 全 0，见下），
> 所以它和 7.2 的 `SAM3_1017` 不是同一个实验。

### 7.2 口径 B：CAMO + COD10K 全量约 8,275 张（`SAM3_1017`，**含训练图**）

| 规模 | 组成 | MAE ↓ | 其它指标 |
|:---|:---|:---:|:---|
| **约 8,275 张** | 训练 CAM 子集 4,040 + 测试集 4,250（CAMO 250 + COD10K 4,000） | **0.0697** | Sm / Fβw / adpF1 / adpIoU **待重测** |

> **这个数字含训练图**：分母里的 4,040 张是模型训练时见过 GT 的图（名义合计
> 4,040 + 4,250 = 8,290，实际参与统计 **8,275** 张），因此它是
> 「训练集 + 测试集」合并的 mean MAE，**偏乐观，不能当作泛化精度**；
> 与 7.1 的 0.0632 **分母不同，不可直接比较**（相减没有意义）。
>
> 「先验是否带来提升」必须在**同一 4,250 张测试集**上分别跑
> `MyTest_SAM3.py --prior_mode real` 与 `--prior_mode zero` 再用 `eval_metrics.py` 对比；
> 这一步**目前尚未做**，所以本节不做任何「提升/下降几个点」的判断。
>
> 权重在服务器 `model_pth/SAM3_1017/`。Sm/Fβw 等指标要先用 `MyTest_SAM3.py` 落盘
> 预测图、再用 `eval_metrics.py` 统一重算，**没有跑就不填数**。

```bat
python eval_metrics.py ^
  --pair baseline:results/OUR/CAMO:Dataset/TestDataset/CAMO/GT ^
  --pair sam3:results_sam3/SAM3/CAMO:Dataset/TestDataset/CAMO/GT ^
  --out outputs/metrics/layer0_camo.json --csv outputs/metrics/summary.csv
```

**更关键：那次 “SAM3” 实验里先验大概率根本没进网络。**
`model_pth/SAM3/log.log` 记录的配置是 `prior_root='./prior_sam3/'`，而该目录在本机
**不存在**；`dataloader_sam3._load_prior` / `MyTest_SAM3.load_test_prior` 对缺失文件
**静默返回全 0 先验**，于是“先验模型”实际是一条恒为 0 的死分支。且原始候选
（`sam3_regions/`）只覆盖 1000/7000 张训练图（缺的 6000 张全是 COD10K），
即使当时目录存在，训练时也有 86% 的样本先验为 0。
→ 现已加入 `check_prior_coverage()` 强制自检（`--prior_mode real` 且 0 覆盖时直接报错）。

## 八、已知问题与优化方向

### 已修复问题（2026-10-17）：DP 拖慢 70× 与参数误用

| 问题 | 根因 | 修复 |
|:---|:---|:---|
| `--gpus 1,2` 时 19.06 s/step，比单卡 0.271 s/step 慢 **70 倍** | PCIe-only 机器（无 NVLink）上 `DataParallel.replicate()` 实测仅 **2.2 GB/s**，每步还要在 GIL 上排队 ~2834 个 kernel launch；模型很小，通信与 launch 开销完全盖过并行收益 | `--dp` 改为**显式开关、默认关**；只写 `--gpus 1,2` 会自动降级单卡并打印原因（`MyTrain_SAM3.resolve_gpus`） |
| `--batchsize 1` 崩溃 | CBAM 里 `BatchNorm2d` 收到 `[1,4,1,1]` | `check_args()` 在分配显存前直接退出，并提示 ≥2 |
| `--dp` + `batchsize % n_gpus != 0` 时某张卡空转 | `torch.chunk` 静默丢弃余数 | 开 `--dp` 时要求整除且每卡 ≥ 2 |
| 多尺度写死在代码里 | `size_rates = [0.75, 1]` | 变成 `--size_rates`（默认值不变，可直接 `--size_rates 1` 提速） |
| `hybrid_e_loss` 每步多两次整幅 `repeat` 拷贝 | `mean().view(...).repeat(...)` | 改 `keepdim=True` + `expand_as` |
| 日志只有 s/step，看不出吞吐 | — | `[Train]` 行追加 **img/s**；新增 `tools/bench_step.py` 分段压测 |

### 已修复问题（2026-10-15）

**Step1 标注管线"看不见伪装目标"（已修复）**

服务器全量跑 Step1 时出现「大量 `SKIP (no tags)`」＋中途 `AttributeError: 'int'
object has no attribute 'get'` 崩溃。定位到 3 个独立问题：

| 问题 | 根因 | 修复方案 |
|:---|:---|:---|
| 崩溃：`'int' object has no attribute 'get'` | Qwen 对「编号框命名」任务回了裸 JSON 数组 `[1, 2]`，`_parse_multi_target` 原样返回，上层 `r.get("tags")` 对 `int` 调用 | 新增 `_normalize_items()` 作为唯一出口：非 dict/非字符串条目（int/None/嵌套列表）与背景词、纯数字、坏 bbox 一律丢弃，垃圾回复退化成空列表而不是异常 |
| 大量 `SKIP (no tags)` | OpenCV 显著性在伪装图上有 20%~46% 的概率**一个候选都找不到**（候选中位数=1），旧逻辑此时回落「开放式提问」，3B 模型答不出对象名甚至返回 `{"tags": []}`，这些图**不会写入 json** | 候选为空时改用 `fallback_boxes()`：整图 + 四象限（12% 重叠）画编号框，让 Qwen 只做"命名"这一件它会做的事；解析失败再用整图框重试一次。图像本身读不出来才回落 legacy（`--box_fallback quad/whole/off`） |
| Gate1 覆盖率被高估 | NonCAM 图（2960 张）注定拿不到标签，却计入分母 7000，`0.30×7000≈2100` 相当于 CAM 子集 4040 的一半 | 默认跳过 NonCAM（`--noncam_policy skip_train`，与 `dataloader_sam3.is_noncam` 同一规则），Gate1 分母改为 CAM 子集 4040；同时清理旧 json 里本 split 的 NonCAM 条目 |

顺带修掉的解析问题：`_parse_multi_target` 旧分割正则 `\]\s*,\s*` 会把**除最后一项
以外所有条目的 `]` 吃掉**（`fox [68,73,279,274], lizard [...]` 里 fox 的框丢失），
已改为 lookbehind 分割；开放式提问的整句反驳（如 "I cannot see any camouflaged
object in this image"）不再被当成 tag 存进 json（否则会被 Step2 当作 SAM3 文本
prompt 用掉）。

修改文件：`llm_annotator.py`、`run_server_pipeline.py`（新增 `--ann_box_fallback` /
`--noncam_policy`，Gate1 分母与提示文案同步）、`make_server_bundle.py`（打包新测试）

回归测试：`python tests/test_step1_annotator.py` —— 47 项全通过，无需 GPU / 无 Qwen 权重；
含崩溃复现（`prescreen_generate_multi` 收到 `[1, 2]`）、兜底框几何、NonCAM 过滤与
json 清理、以及与 `dataloader_sam3.is_noncam` 在 7000 个文件名上的一致性检查。

### 已修复问题（2026-10-11）

**Step 3 Qwen 视觉提示 bug（已修复）**

Qwen 模式在 Step 3 中几乎全部 fallback 到 heuristic，根本原因有 3 个：

| 问题 | 根因 | 修复方案 |
|:---|:---|:---|
| System prompt 冲突 | `generate_with_text` 硬编码 `"Output only JSON"`，与 "只输出数字" 指令矛盾 | 增加 `system_prompt` 参数，Step 3 传入专用 prompt |
| 视觉提示太弱 | `draw_candidates` 只画 2px 细轮廓 + 小号文字，Qwen 3B 看不清 | 改为 3px 粗矩形框 + 大号标签 + 填充背景 |
| n=1 时仍调用 Qwen | 只有 1 个候选时没必要让 Qwen 选择，且 Qwen 容易输出越界数字 | n=1 时直接返回唯一候选，跳过 Qwen |

修改文件：`llm_annotator.py`（`generate_with_text` 签名）、`region_selector.py`（`draw_candidates` + `qwen_select`）

### 已知限制

1. **Qwen 3B 标注质量有限**：对高度伪装图片识别率低，常用泛化描述（如 "bird" 而非精确描述）
2. **中文 prompt 问题**：3B 模型中文能力弱，已在代码中改为英文 prompt
3. **Step1 推荐 prescreen 模式**：OpenCV 做显著性检测 → 画编号框 → Qwen 只需命名，降低 3B 模型的任务难度；显著性漏检时由「整图 + 四象限」兜底框补位（`--box_fallback quad`，默认开）

### 未来优化方向

1. **SAM3 Fine-tuning**：在 COD 数据集上微调 SAM3，改善伪装区域分割
2. **更强 Qwen 模型**：72B 模型标注质量显著高于 3B（代价：推理时间 x24）
3. **两阶段标注**：3B 粗标注 + 72B 精炼（成本仅为 72B 的 1/10）
4. **先验质量提升**：优化 SAM3 区域选择策略，减少错误先验
5. **负样本利用**：先验为"无人目标"时用黑图训练，显式学习"无目标时输出全黑"

### 与旧 `run_server_pipeline.sh` 的差异

| 旧版问题 | 现状 |
|:---|:---|
