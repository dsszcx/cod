# 全量 RGB 训练工程验收（2026-10-26）

## 为什么先做这一步

官方 SINet-V2 权重的标准测试指标已经对齐，但自研模型此前只有128训练/32验证的小开发实验，不能直接与官方论文表竞争。全量4035张训练/开发图的区域先验尚未备齐；纯RGB基线不应该因此不能运行。

检查发现 `train_pilot.py` 无条件检查每张图的 `region_package`，与 `RelationDataset(arm='rgb')` 实际完全不读取先验的行为不一致。现改为仅含RGB时不要求先验，任何包含直连/关系的条件仍严格要求真实先验；没有用假空先验替代缺失数据。

另新增显式 `manifest_files` 开关，默认仍是 `pilot_train.csv / pilot_val.csv`，全量验收明确指定 `train.csv / val.csv`。既有实验的默认数据、初始化、优化器和损失均不变。训练核心RGB/直连/关系优化回归、本地和服务器RGB清单回归通过。

## 固定设置及边界

- 原有CAM-only清单：3652 train、383 val，固定成员，不重新抽样；无NonCAM。
- 自研PVTv2-B2 RGB模型，channel64、原配置；ImageNet骨干初始化，随机COD解码器。不是Res2Net版官方SINet，也不加载官方SINet分割权重。
- seed20261022，352×352，batch8，FP32，AdamW lr1e-4 / weight decay1e-4，既有四输出结构损失、裁剪范数1；一轮457次更新。
- 原有确定性/TF32设置，仍可能有PyTorch算子非确定性警告，不承诺跨硬件逐位一致。
- **仅1 epoch，是工程验收，不是收敛训练，不是方法有效性实验。** 本轮不运行Qwen/SAM3、不训练质量头、不使用官方测试集。
- best仍按原有raw验证MAE规则，仅一轮没有事后多轮挑选；最终四指标全部来自同一份保存概率、同一checkpoint。
- raw与标准PNG口径分别汇报MAE、S、mean E、weighted F，按总体以及CAMO/COD10K开发样本分组。标准口径复用已核验的官方适配器；相同uint8量化在内存中执行，不重复导出PNG。不会将开发集数字与官方测试集表混排竞争。

## 运行与产物

服务器独立源码 `/srv/cod-project/releases/rgb_full_data_acceptance_20261026_v1`，日志 `RUN.log`；输出 `/srv/cod-project/outputs/RGB_FULL_DATA_ACCEPTANCE_20261026_V1`。GPU1，只有任务本身的训练进度日志，没有额外进程监控。使用之前已存在的私有CPU指标依赖，不改全局环境。

入口 `tools/server/rgb_full_acceptance_20261026.sh`，先回归再生成固定计划，再训练一轮，再计算两套四指标。已正常结束，退出码0；`METRICS.json` 为DONE，383张概率覆盖完整，出现 `RGB_FULL_ACCEPTANCE_BATCH_DONE`。训练及验证约268.1秒，457次更新，无非有限损失或梯度错误；指标计算额外用时不计入该训练摘要。汇总、逐图指标、配置、计划及日志已取回本地 `outputs/RGB_FULL_DATA_ACCEPTANCE_20261026_V1`，权重和原尺度概率保留服务器。

两套指标基于同一1-epoch checkpoint的同一383张预测；raw MAE精确复核训练日志的选模值。两套口径不同，不把两行差异解释为模型改进。该实验验证全量数据、训练和评估接口可用，不证明收敛、稳定泛化、语义关系收益或优于官方SINet-V2；它也不能与之前128/32、batch2短训表直接比较。

本地官方权重已从 Downloads **移动**到 `model_pth/SINet_V2/Net_epoch_best.pth`，哈希不变、服务器副本保留。本次RGB训练不使用该权重。

验收通过后，仍需预先固定正式训练的轮次、学习率计划和各消融组相同训练预算，并完成区域先验覆盖，才进入正式模型比较。本轮不自动启动长期正式训练或把开发验证用于测试集调参。
