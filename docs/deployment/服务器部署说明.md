# 服务器部署说明（SAM3 伪装目标检测 · 一键全流程）

> 适用包：`server_bundle_sam3_20261015.zip`（36 个文件，97.3 MB，含 `pretrained/pvt_v2_b2.pth`）
> 入口脚本：`run_server_pipeline.py`（纯标准库）+ `run_server_pipeline.sh`（薄封装）
> 目标：**先把上一次的产出删干净，再重新生成 train/test 两套先验并训练**，全程有闸门拦截“静默死先验”。

## 0. TL;DR（三条命令）

```bash
# ① 解包到工作根目录（服务器上的代码/数据/产出都在这一个目录里）
unzip -o server_bundle_sam3_20261015.zip -d /srv/cod-workspace     # 或 python3 -m zipfile -e <zip> <dir>
cd /srv/cod-workspace

# ② 先看计划：会删什么、每一步会跑什么命令（零副作用）
bash run_server_pipeline.sh --dry-run --yes

# ③ 一键跑（默认 --fresh：先删旧产出，再 Step1→5）
bash run_server_pipeline.sh --fresh --yes 2>&1 | tee run_$(date +%m%d_%H%M).log
```

不建议一上来就跑全量：先按 §3.3 用 `--max-images 50` 冒烟，再跑全量。

## 3. 怎么跑

### 3.1 先看计划（零副作用，务必先做）

```bash
bash run_server_pipeline.sh --dry-run --yes
```

`--dry-run` 会：
* 列出**待删除清单**（路径、文件数、占用空间、合计），但**不会真删**；
* 打印 Step1-5 每一条将执行的完整命令（可直接复制单独跑、便于排查）；
* 闸门在 dry-run 下只报告比率**不中止**（因为此刻读到的还是上一轮的旧文件）。

看的时候重点核对：图片数（7000 / 250 / 4000）、GPU 号、`--qwen_model`、`--sam3_ckpt`、
`prior`/`regions` 目录名、以及“合并图片视图”一行（test 会合并 CAMO+COD10K）。

### 3.2 真跑

```bash
# 全流程（Step1→5），先删旧产出
bash run_server_pipeline.sh --fresh --yes 2>&1 | tee run_all.log

# 只清理旧产出（什么都不跑）
bash run_server_pipeline.sh --purge_only --yes

# 只生成先验（Step1/2/3），多卡并行
bash run_server_pipeline.sh --step 1,2,3 --gpus 0,1,2 --yes

# 只训练+推理（先验已在，保留旧产出，别再删）
bash run_server_pipeline.sh --keep --step 4,5 --yes

# 50 张冒烟（验证环境和命令拼装，几分钟）
bash run_server_pipeline.sh --fresh --step 1,2,3 --max-images 50 --yes
```

`--fresh` 是**默认行为**（等价于显式写出）；想保留旧产出请用 `--keep`。

### 3.3 推荐节奏（服务器上最省事的顺序）

| 步骤 | 命令 | 说明 |
|:---|:---|:---|
| 1 | `--dry-run --yes` | 核对计划 |
| 2 | `--fresh --step 1,2,3 --max-images 50 --yes` | 50 张冒烟，通不过就别上全量 |
| 3 | `--fresh --step 1,2,3 --gpus 0,1,2 --yes` | 全量先验（本次会删掉②的产物，正常） |
| 4 | `--keep --step 4,5 --yes` | 训练 + 推理（**不要再加 --fresh**） |

> ⚠️ 分多次执行时，第 2 次起务必用 `--keep`。脚本对 `--fresh + 局部 --step` 的组合会打
> `WARN`，对 `--fresh + --step 4/5` 这种会**直接报错退出**，防止把刚生成的先验删掉。

## 4. 会删什么、不会删什么

`--fresh` 的默认清单（相对 `--root`，**通配符只匹配目录**，避免误伤同名源码文件）：

| 目标 | 内容 | 全量大小量级 |
|:---|:---|:---|
| `outputs/` | `prior_annotations.json` + `metrics/` + `prior_quality/` 报告 | ~1 MB |
| `sam3_regions*` | Step2 候选区域 npz | ~45 GB（11250 个 npz，≈4.1 MB/图） |
| `prior_sam3*` | Step3 最终先验（含 `prior_sam3_0814/`、`prior_sam3_sel/` 等历史目录） | ~95 GB（≈8.5 MB/图） |
| `results_sam3*` | Step5 预测图（含 `results_sam3_repro*` 等） | 几十 MB |
| `model_pth/SAM3/log.log` | 上一轮训练日志 | 100 KB |
| `_pipeline_tmp/` | 本脚本的 test 合并图片视图（symlink） | 几乎不占空间 |

**不会删**：`Dataset/`、`sam3-main/`、`pretrained/`、`lib/`、`templates/`、`.git/`、
`model_pth/**/*.pth`（权重一律不动）。兜底保护逻辑：

1. 只允许删 `--root` **之下**的路径（不许删 root 本身、不许越界）；
2. 目录名命中保护名单（`Dataset`/`TestDataset`/`pretrained`/`sam3-main`/`lib`/`templates`… ）直接跳过；
3. 带通配符的模式只匹配目录，`sam3_regions*` 不会碰到 `sam3_regions.py`；
4. 删除前打印清单 + 合计大小，并要求确认（`--yes` 才免确认；stdin 非 TTY 时强制要求 `--yes`）。

自定义：

```bash
bash run_server_pipeline.sh --purge-only --purge-extra 'prior_sam3_0814' --yes   # 额外删
bash run_server_pipeline.sh --purge-only --purge-keep outputs --yes              # 保留 outputs/
```

`model_pth/SAM3/` 下 53 个历史权重**不在**默认清理范围。若想让 Step5 的“自动选最新权重”
不会挑到 3ch/7ch 老文件，加 `--archive-stale-ckpt`（把非 8ch 的移到
`model_pth/SAM3/_stale_pre8ch/`，是移动不是删除；默认关闭，因为它是**全部**历史权重）。

## 5. 闸门（Gate）与退出码

每个 split 的 Step1/2/3 各跑完后**立刻**做覆盖率检查；Step4 之前如果先验是死的，这里就拦住。

| 闸门 | 比较 | 默认阈值 | 触发阈值说明 |
|:---|:---|:---|:---|
| Gate1 标注覆盖 | `prior_annotations.json[split]` 条数 ÷ 图片数 | `--min-ann-ratio 0.30` | Qwen3B 在伪装图上召回有限；<70% 会额外 WARN |
| Gate2 区域覆盖 | `sam3_regions/{split}_*.npz` ÷ 标注条数 | `--min-region-ratio 0.99` | SAM3 逐图处理，正常应 100% |
| Gate3 先验覆盖 | `prior_sam3/{split}_*.npz` ÷ 区域 npz | `--min-prior-ratio 0.99` | 逐 npz 处理，正常应 100% |
| Gate4 先验非空 | `target_mask` 全 0 的 npz 占比 | `--max-zero-prior-ratio 0.50` | **本机历史实测 0.208 / 0.316**，>0.30 会 WARN |

阈值依据（本机对已有产物实测，供你按服务器实际数据调整）：

* `prior_sam3_0814`（heuristic 选择）：全 0 先验 **52/250 = 20.8%**；
* `prior_sam3_sel`：**79/250 = 31.6%**；
* `sam3_regions` 抽样 300 个：**64/300 的 masks 为空**（SAM3 在该图上没返回任何候选）——
  所以 Gate2 只核对“文件数”，不核对“候选非空”。

退出码：

| 码 | 含义 | 处理 |
|:---|:---|:---|
| `0` | 成功（或 dry-run 结束） | — |
| `1` | 预检失败 / 某一步命令返回非 0 / 用户取消 | 看日志最后一条 `ERROR:` |
| `2` | **闸门未通过**（覆盖率不足或全 0 先验过多） | 修上游，或明确知情后用 `--force` 继续 |

`--force` 只放行 Gate1-4，**不放行**预检（缺文件/缺模型仍会退出 1）。
Gate4 的扫描会逐个读 npz，全量 11250 个约几分钟；想跳过用 `--skip-zero-scan`
（**不建议**：这条正是当年“先验恒 0 却静默训练”的拦截器）。

## 6. 权重与 8ch 事实（很重要）

`check_ckpt_channels.py` 在本仓库扫描到的 53 个 `.pth`：

```
>>> [ckpt-check] in_chans histogram: 3:17, 7:36
>>> [ckpt-check] 53 file(s) do NOT match in_chans=8
```

即**没有任何一个 8ch 权重**：

| 权重类型 | 数量 | 含义 |
|:---|:---:|:---|
| 3ch | 17 | 基线 PVTv2（`model_pth/OUR/`） |
| 7ch | 36 | SAM3 v3（RGB+target+aux×3，**没有 neg_flag**） |
| **8ch** | **0** | 当前 `Network_SAM3` 需要的（RGB+target+aux×3+**neg_flag**） |

结论：`model_pth/SAM3/KKK_best_41.pth`（7ch）**不能**用于推理/续训，Step5 会在加载前被拦下：

```bash
python check_ckpt_channels.py model_pth/SAM3/KKK_best_41.pth --expected 8 --strict --no-probe-networks
# 退出码 1：GUARD_BLOCKED
```

所以：**必须 Step4 重新训练**，跑出 8ch 的 `KKK_best_*.pth` 之后再 Step5。
不要在 Step5 用 `--pth` 指到老权重上（会以 rc=1 中止，这是设计如此）。

## 7. 分环境执行 / 断点续跑

Step1/3 需要 Qwen（`cx2`），Step2/4/5 需要 SAM3+torch（`cx1`）。分环境跑法：

```bash
# --- cx2 环境：标注 + 区域选择 ---
conda activate cx2
bash run_server_pipeline.sh --step 1,3 --yes            # 首次；之后续跑用 --keep
# --- cx1 环境：SAM3 区域 + 训练 + 推理 ---
conda activate cx1
bash run_server_pipeline.sh --keep --step 2,4,5 --yes
```

注意：

* `run_server_pipeline.sh` 用 `PYTHON` 环境变量选解释器：
  `PYTHON=/opt/conda/envs/cx1/bin/python bash run_server_pipeline.sh ...`；
* Step2 依赖 Step1 的 `outputs/prior_annotations.json`，Step3 依赖 Step2 的 npz —— 分环境时**顺序不能乱**，
  且第 2 段必须 `--keep`（否则删掉第 1 段的成果）；
* Step1/2/3 默认 `--resume`（已有结果跳过），中断后重跑只补缺口；要重做请加 `--no-resume`（或 `--fresh`）；
* 多卡：`--gpus 0,1,2` 同时作用于 Step1（spawn 多进程）、Step3（spawn 多进程）、Step4（DataParallel）；
  Step2/Step5 用第一张卡（`CUDA_VISIBLE_DEVICES=<gpus[0]>`）。

## 8. 磁盘 / 时间预算

全量 = train 7000 + test 4250 = **11250 张图**。

| 阶段 | 中间产物 | 规模 | 备注 |
|:---|:---|:---|:---|
| Step2 | `sam3_regions/` | **≈45 GB**（11250 × ≈4.1 MB） | box-prompt，逐图一次 |
| Step3 | `prior_sam3/` | **≈95 GB**（11250 × ≈8.5 MB） | 1×target + 3×aux，原图尺寸 float32 |
| 合计 | 先验链路 | **≈140 GB** | 预检默认要求剩余 ≥150 GB（`--min-free-gb`） |
| Step4 | `model_pth/SAM3/*.pth` | ≈100 MB/个（每 10 epoch 存一个 + best） | 8 卡/单卡取决于显存，`--batch 6` 是默认 |
| Step5 | `results_sam3/<run>/` | ≈34 MB（4250 张 png） | 与旧结果同量级 |

时间上真正的大头是 **Step1 与 Step3 的 Qwen 推理**（各 ≤11250 次 3B 推理）与 **Step4 训练**
（80 epoch × (7000/batch) 迭代，且每轮还要在 4250 张测试图上算 MAE）。
建议先跑 50 张冒烟，从日志时间戳读出单张耗时再外推：

```bash
bash run_server_pipeline.sh --fresh --step 1 --max-images 50 --gpus 0,1,2 --yes
# 看日志里 50 张用了多少秒 -> 单张耗时 × 11250 ÷ 卡数 = Step1 预计
```

并发建议：`--gpus 0,1,2`（Step1/3 都是 spawn 子进程按 GPU 分片，显存占用与单卡一致）。

## 9. 验收标准（跑完对着数）

| 检查项 | 期望 | 命令 |
|:---|:---|:---|
| 标注条数 | train/test 均 > 30% 图片数 | `python -c "import json;d=json.load(open('outputs/prior_annotations.json'));print({k:len(v) for k,v in d.items()})"` |
| 区域 npz | `train_*` = 标注条数，`test_*` = 标注条数 | `ls sam3_regions/train_*.npz \| wc -l` |
| 先验 npz | `train_*`/`test_*` 均 = regions 且 > 0 | `ls prior_sam3/train_*.npz \| wc -l` |
| 全 0 先验 | ≤ 50%，最好在 20%–35% | 脚本末尾 `GATE 4 先验非空` 一行 |
| 权重通道 | 8ch | `python check_ckpt_channels.py --glob 'model_pth/SAM3/*.pth' --strict` |
| 预测图 | CAMO 250 + COD10K 4000 = **4250** 张 | `ls results_sam3/<run>/CAMO/*.png \| wc -l` |
| 指标 | 用唯一口径 `eval_metrics.py` | 见下方 |

跑完脚本会打印“产出汇总”（各目录文件数与大小、npz 计数、ann 计数）和下一步评估命令：

```bash
python eval_metrics.py \
  --pred_dir results_sam3/<run>/CAMO --gt_dir Dataset/TestDataset/CAMO/GT --name sam3_camo
python eval_metrics.py \
  --pred_dir results_sam3/<run>/COD10K --gt_dir Dataset/TestDataset/COD10K/GT --name sam3_cod10k
# 想和基线一起对比： --pair baseline:results/OUR/CAMO:Dataset/TestDataset/CAMO/GT
```

⚠️ 默认协议是 `sigmoid × 255`（`MyTest_SAM3.py` 默认，不加 `--minmax`）。
`results/`、`results_sam3_repro*` 等**老**预测图是 min-max 拉伸过的，评测它们要加 `--minmax`，
否则数字不可比（见 `docs/experiments/Layer0证据报告.md`）。

## 10. 常见问题

| 现象 | 原因 | 处理 |
|:---|:---|:---|
| `GATE 1 标注覆盖 ... 14.29%` 然后 exit 2 | 读到的还是旧的 CAMO-only 标注（1000/7000），旧产出没删 | 用 `--fresh`（默认）或先 `--purge-only` |
| `GATE 3 先验覆盖 0/1000` exit 2 | `prior_sam3/` 不存在或 Step3 没跑成功 | 先跑 `--step 1,2,3`；确认 `--prior` 指向 Step3 的 `--out` |
| `ERROR: 预检失败 ... Qwen 模型目录不存在` | 路径不对 | `--qwen-model /opt/models/Qwen2.5-VL-3B-Instruct/` |
| `ERROR: 预检失败 ... 磁盘剩余 x GB < 150` | 空间不足 | 清盘 / `--min-free-gb 100`（自行承担风险） |
| Step5 `rc=1` 且日志里是 `in_chans=7` | 用了 7ch 老权重 | 先 Step4 训出 8ch；或 `--archive-stale-ckpt` 后再跑 |
| `assert opt.image_root is not None` | 手写 Step3 命令漏了 `--image_root` | 用本脚本（总会传 `--image_root`），或手动补上 |
| 日志中文乱码 | 终端/文件编码 | `PYTHONIOENCODING=utf-8 LANG=C.UTF-8 bash run_server_pipeline.sh ...` |
| `stdin 不是交互终端` | nohup/管道下没给 `--yes` | 加 `--yes` |
| test 合并视图 symlink 失败 | 跨文件系统或无权限 | 自动退化为**复制**（会多占约 2–3 GB 图片空间，日志里 `copy=N`） |
| `--fresh` 被拒绝 | `--fresh` 与 `--step 4/5` 冲突（会删先验） | 用 `--keep` |
| 想看每一步到底跑了什么 | — | 全程 `--dry-run`，或看日志里 `RUN <完整命令>` |

## 11. 主要参数速查

| `--root` | `/srv/cod-workspace` | 工作根目录（数据/代码/产出） |

| `--ann_mode` | `prescreen` | Step1 模式（`prescreen`/`legacy`） |

## 13. 2026-10-17 先验瘦身（78 GB）与训练提速

### 13.1 现象与根因

`prior_sam3/` 共 78 GB（8275 个 npz），**最大单文件 578 MB**（原图最大 3592×2386）。
原因：Step3 用 `np.savez`（不压缩）把 `target_mask` + `aux_masks` 以 **float32 按原图分辨率**写盘；
Step4 的 loader 每取一个样本都要把这 4 个平面（约 34–86 MB）读进来再缩到 352。

实测（4 workers）：`[data]` p50 = 85 ms、p99 = 1019 ms、**max = 1708 ms/样本**；
80 个 epoch 要走 6.2 TB 磁盘读，并与机器上其他用户的训练任务抢盘。

### 13.2 先验新格式（`--prior_size`，默认 448）

- 形状固定 `target_mask (1,448,448)` + `aux_masks (3,448,448)`；
- 数据类型 `uint8` 0/1，`np.savez_compressed`；
- 下采样 = 面积平均（PIL BOX）+ “有任何覆盖即 1”，等价于二值掩码的 max-pool，
  **细长目标不会被丢掉**；
- `target_tag` / `bbox` 原样保留。

448 = 352 的 1.27 倍，继续放大/裁剪后仍有余量。整目录预计 **0.3 GB 左右**（小 200 倍以上）。

> 下游**无需改代码**：`dataloader_sam3._load_prior`（`.astype(float32)` → `clip*255`）与
> `load_test_prior`（`.float()`）本来就接受 uint8 0/1。只要把 `--prior_root` 指到新目录即可。

### 13.3 把现有 78 GB 先验转成新格式（不重跑 Step1–3）

```bash
cd /srv/cod-workspace
python tools/compact_priors.py --src prior_sam3 --dst prior_sam3_c448 \
       --size 448 --jobs 8 --verify 300
du -sh prior_sam3 prior_sam3_c448
```

通过标准（脚本自动判定，失败返回 1）：

| 检查 | 阈值 |
|:---|:---|
| 目标目录总大小 | < 2 GB |
| 最大单文件 | < 200 KB |
| 先验 IoU（原图 vs 新格式，重采样到 352） | mean ≥ 0.98、p5 ≥ 0.95 |

`--verify` 的 IoU 检查是“下采样会不会毁掉细长目标”的实证；不达标就把 `--size` 提到 512 重跑。
**不要删 `prior_sam3/`**，确认新目录可用后再清。

若服务器上没有这个脚本，等价的一行式做法（逻辑相同，只是不带 IoU 校验）：
用 `python - <<'PY'` 把 `tools/compact_priors.py` 的 `resize_binary_mask` + `savez_compressed`
逻辑抄进去直接跑即可 —— 但**推荐直接上传该文件**，它带断点续跑（已存在的 npz 跳过）与闸门。

### 13.4 Step4 新增参数（同步全部 6 个文件后再用）

| 参数 | 默认 | 作用 |
|:---|:---|:---|
| `--workers` | 8 | DataLoader 进程数；`0` = 主进程加载（排查 fork-CUDA 卡死时用） |
| `--aug_mode fast` | fast | 先缩到 1.25×trainsize（448）再随机裁剪/旋转/翻转，**不再按 3592×2386 缩放 4 个掩码平面** |
| `--aug_mode legacy` | — | 旧行为（原图分辨率增强），只用于复现 2026-10-17 之前的数字 |
| `--log_interval` | 10 | 每 N 步写一行 `[Train]`，含 **s/step** |
| `--mp_context` | fork | 卡死时改 `spawn` |
| `--no_benchmark` | 关 | 关掉 `cudnn.benchmark`（它每个新 shape 都要重新调优，前 ~10 步会慢 30 倍，这是“看起来卡住”的常见原因） |
| `--prior_size`（流水线） | 448 | 透传给 Step3；`0` = 旧的原图分辨率 float32 |

`run_server_pipeline.py` 已把 `--workers` / `--aug_mode` / `--prior_size` 透传给 Step3/Step4，
所以**必须把 `run_server_pipeline.py`、`MyTrain_SAM3.py`、`dataloader_sam3.py`、`region_selector.py`、
`llm_annotator.py` 一起上传**：老 trainer 不认识新参数会直接 argparse 报错。

## 十四、单卡优先：DataParallel 的 70× 陷阱（2026-10-17 实测）

### 14.1 先看结论

| 配置 | 实测 s/step（2 个 size_rate，bs=6，352px） |
|:---|:---:|
| **单卡**（默认，`--gpus 1`） | **0.271 s** |
| DP 2 卡（`--gpus 1,2 --dp`） | **19.06 s**（≈70× 慢） |

这台机器**没有 NVLink**，`DataParallel.replicate()` 只能走 PCIe，实测 **2.2 GB/s**；
模型本身很小（batch3@352 的前向+反向只有 92 ms），每步却有 ~2834 个 kernel launch
要在 GIL 上排队 —— 并行收益远远小于通信 + launch 开销。

> 因此 `--dp` 现在是**默认关闭的显式开关**。只写 `--gpus 1,2` 而不带 `--dp` 时，
> `MyTrain_SAM3.py` 会自动只用第一张卡并打印：
> `WARNING: --gpus 1,2 给了 2 张卡，但 --dp 未开启 -> 只用 1`。
> **以前那种“多给几张卡就更快”的直觉在这台机器上是错的。**

### 14.2 复现 / 定位慢在哪一段

```bash
cd /srv/cod-workspace
python tools/bench_step.py --mode full --prior_root prior_sam3_c448 \
  --batchsize 6 --workers 8 --iters 20
# 只测 GPU 侧、完全不读盘：
python tools/bench_step.py --mode step --synthetic --batchsize 6
# 想亲眼看 DP 变慢（不建议真跑训练）：
python tools/bench_step.py --mode step --synthetic --gpus 1,2 --dp
```

`--mode` 四档：`data`（只取数）/ `rates`（H2D + 插值）/ `step`（+ 前向/损失/反向）/
`full`（取数 + step，与日志 s/step 同口径）。`full` 会自动打印 data/step 拆解比例。

判读：
- `data` 占大头 → 先验 IO / 增强慢：用 `--aug_mode fast`、`prior_sam3_c448`、加 `--workers`；
- `step` 占大头 → 算力：`--amp`、加大 `--batchsize`、`--size_rates 1`；
- `step` 单卡只有 0.1 s 量级却实测 ~9 s → 就是踩到 DP，去掉 `--dp`。

### 14.3 新增的参数与硬闸门

| 参数 | 默认 | 说明 |
|:---|:---|:---|
| `--dp` | **关** | 显式开启 DataParallel；只有确认机器有 NVLink 才值得开 |
| `--size_rates` | `0.75,1` | 每步的缩放序列；`1` = 单尺度，最快；写 `0.75,1` 才是出 0.0697 的配方（该 0.0697 是 CAMO+COD10K 全量约 8,275 张、**含训练图**的合并 MAE，见 README §一） |
| `--amp` | 关 | bf16 autocast **只包前向**，损失仍 fp32，不需要 GradScaler；老卡（< Ampere）会自动关闭 |

在分配显存之前就会退出的硬闸门（`MyTrain_SAM3.check_args`）：

| 条件 | 原因 |
|:---|:---|
| `--batchsize 1` | CBAM 的 `BatchNorm2d` 会收到 `[1,4,1,1]`，直接 ValueError |
| `--dp` 且 `batchsize % n_gpus != 0` | `torch.chunk` 静默丢弃余数，有卡空转 |
| `--dp` 且 `batchsize // n_gpus < 2` | 每卡 1 张，同样触发 bs=1 的 BN 崩溃 |
| 最小 `size_rate × trainsize` < 64px | 插值后尺寸退化 |

所以 `--dp` 下合法的 `batchsize` 是 `2×卡数` 的倍数：2 卡 → 4/6/8…，4 卡 → 8/12/16…
（6 张分 4 卡不合法：`6 % 4 = 2`。）

### 14.4 `CUDA_VISIBLE_DEVICES` 的坑（会二次过滤）

`MyTrain_SAM3.py` 里是 `os.environ["CUDA_VISIBLE_DEVICES"] = opt.gpus`，
而 **torch 会先看环境变量再映射 `--gpus` 的编号**。如果 shell 里残留：

```bash
export CUDA_VISIBLE_DEVICES=2,3
python MyTrain_SAM3.py --gpus 0     # 实际用的是物理 2 号卡，不是 0 号
```

排查时先清干净：

```bash
unset CUDA_VISIBLE_DEVICES
nvidia-smi --query-gpu=index,name,memory.used --format=csv
python MyTrain_SAM3.py --gpus 1 ...
```

`tools/bench_step.py` 和 `run_server_pipeline.py` 走同一套 `resolve_gpus`，行为一致。
