## 问题 1：PowerShell 不支持 `&&` 命令连接符

- **时间**：2026-07-28
- **环境**：Windows PowerShell 5.x
- **现象**：执行 `cd xxx && Get-ChildItem` 报错 `标记"&&"不是此版本中的有效语句分隔符`
- **原因**：`&&` 是 PowerShell 7+ 的新特性，5.x 只支持 `;`
- **解决方案**：所有命令改用 `;` 分隔
- **状态**：✅ 已解决

## 问题 2：训练集/测试集 GT 文件数量不匹配

- **时间**：2026-07-28
- **环境**：本地数据集
- **现象**：`TrainValDataset` 的 Imgs(1000) : GT(1250)，`TestDataset/CAMO` 的 Imgs(250) : GT(1250)，导致 `filter_files()` 的 assert 断言失败

- **状态**：✅ 已解决

## 问题 13：多尺度训练 rate=1.25 导致显存压力过大

- **时间**：2026-08-13
- **环境**：RTX 4070 Laptop 8GB
- **现象**：多尺度 size_rates=[0.75,1,1.25] 时，1.25 尺度输入 440×440，显存冲到 7.9/8GB，出现卡死风险

- **解决方案**：size_rates 改为 [0.75,1]，batchsize 降到 6，显存降至 2.9GB，训练速度还快了 4 倍
- **状态**：✅ 已解决

## 问题 14：Start-Process 重定向 stderr 时 tqdm 写入阻塞

- **时间**：2026-08-13
- **环境**：Windows + Start-Process -RedirectStandardError
- **现象**：后台训练启动后进度条卡住不推进，CPU 增长缓慢
- **原因**：Windows 管道缓冲满时，tqdm 写 stderr 被阻塞，Python 主循环卡在写操作
- **解决方案**：tqdm 的 file 参数指向 `os.devnull`，日志改走 log.log 文件（logging 直接写文件不受影响）
- **状态**：✅ 已解决

## 问题 15：工具环境 Start-Sleep 不真实等待，导致误判训练卡住

- **时间**：2026-08-13
- **环境**：工具终端
- **现象**：`Start-Sleep -Seconds 600` 后检查，日志几乎没推进，误以为训练卡死；实际当前系统时间只过了 1 分钟

## 问题 22：验证阶段 MAE 计算存在尺度 bug（GT 未归一化到 0-1）

- **时间**：2026-08-13（训练效果分析时发现）
- **环境**：MyTrain.py 的 test 函数
- **现象**：训练 25-29 epoch 时 MAE 恒定在 46.076~46.083 几乎不动，无法反映模型真实进步
- **原因**：`gt = np.asarray(gt, np.float32)` 得到 0-255 范围值，而预测 `res` 是 0-1 范围；两者直接相减导致 MAE 虚高（真实 MAE ≈ 46/255 ≈ 0.18），且每张图 min-max 归一化使指标对训练不敏感
- **解决方案**：`gt = np.asarray(gt, np.float32) / 255.0`；训练效果应以 Loss_AVG 为准（1.77→1.71 稳定下降）
- **状态**：⚠️ 已发现，未修复（不影响训练本身，仅影响验证指标展示）

## 问题 23：断点续训后最佳模型保存逻辑失效（best_state 初始化值错误）

- **时间**：2026-08-13（训练完成后发现）
- **环境**：MyTrain.py 断点续训（--load 从 KKK_best_24 恢复）
- **现象**：恢复训练 25-49 轮，MAE=46.076 与历史最佳持平，但未保存新的 KKK_best 模型
- **原因**：best_state = {"mae": 1, "epoch": 0} 在恢复时重新初始化；而带 bug 的 MAE≈46（GT 未归一化），46 < 1 永远不成立，导致最佳模型保存条件失效；且 epoch 从 25 开始，epoch==1 的强制保存分支也不触发
- **解决方案**：恢复训练时将 best_state["mae"] 初始化为 1e9，或从历史 log.log 解析历史最佳 MAE；MAE bug 修复后（≈0.18 < 1）该问题自动消失
- **状态**：⚠️ 已发现，未修复（当前可用模型为 Net_epoch_40.pth，Loss 更优）
